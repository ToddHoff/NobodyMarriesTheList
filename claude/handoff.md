## Things Todd has told us to keep out of the prose

These are in the style guide; listed here because they were the most frequent notes.

- "Plainly," "never once," and tidy paradoxes such as "a key I never gave him."
- A second clause joined on with ", and" to land a point (Todd, October 8: "This ', and' is a claudism. People don't speak that way"). Two sentences do the job.
- Asides to the reader: "I want that on the record," "I'm not discussing it," "I should say."
- A narrator stopping a scene to state a general principle.
- Opening lines that foreshadow what the narrator has not learned yet.
- Explanations that slow the scene, especially of how scheduling or agents work.
- Trade jargon the reader will not know ("not-to-exceed"; "the box" for the body of the truck).
- Exact figures that add nothing and invite mistakes (ages, hour totals).
- Wordplay that hides what is being referred to. Say the thing. A word used once for something the book calls by another name does the same harm ("cartons" for the gift boxes).
- From his chapter 7 notes: a turn that comes out of the blue. If a character decides something, the reader sees the decision and why it happens at that moment.
- Jokes that reach. If a line is meant to be funny, it has to be funny.
- Not on this list: the narrator's own feelings, in the narrator's voice. On the list: Claude's sentence habits in narration as well as dialogue (see START HERE).

## Working notes for the next session (tools)

These are how the work was done, so a new session does not have to rediscover it.

- Project files are read whole with the Projects tool and written back whole. They come back inline, not as local files, so to change one: write it to the session's working folder (this session used `nmtl/manuscript/` and `nmtl/claude/`), change it there with the Edit tool or a short script, and upload it with `project_write` and `local_path`. - The four docs are edited through the Claude Docs connector, each with a container id and a node id: manuscript `BN9N9RAeM2ivsXGTJKkJPR`, node `c805f203-b28b`; book plan `5CJYnj7TUMirBJnggMvKB2`, node `62f6b9d9-7921`; style guide `VgPGFhrYN9nJwoAxyG7mJQ`, node `f47de152-06fa`; character sheet `GvKwHeT7f2Y6N8yUqVFpyB`, node `5d32e600-566c`.
- To find a paragraph, use a search read (`{"kind":"search","text":...}` or `"pattern"`, at most 256 characters). To change words, use a `replace` with a find target and `"as":"text"`. To cut a sentence, use a `delete` with a find target that includes the leading space. To cut a whole paragraph, use a `delete` with a blocks target (`{"kind":"blocks","ids":[...]}`) plus `ifHash` (the `h` the read printed for that block) and `ifRev` (that read's rev). A new paragraph goes in with an `insert` before or after a block id. Several ops can go in one update call.
- To replace a whole chapter body in the manuscript doc (October 8): first a search read with a pattern for the chapter's first sentence and its last paragraph, which gives the first character id of the body and the last character id. Then `{"op":"delete","target":{"kind":"chars","range":["<first char id>","<last char id>"]}}`. That empties every block in the chapter and the ack lists their ids. Then one call that deletes all of those blocks but the first (`kind":"blocks"` with the ids and `ifRev` from the ack) and replaces the first (`ifHash":"e3b0c442"`, the empty-block hash, and the same `ifRev`) with the new body as markdown. Write each `***` scene break as `\*\*\*` so it lands as text and not as a rule. Do the two calls back to back; between them the chapter is blank in Todd's view.
- Each doc's header time is split across several text runs. A find on the whole old date and time string (for example "Wednesday, October 7, 2026, 10:55 PM PDT") replaces it across the runs; read the paragraph after to check it.
- A paragraph in these docs cannot be centered, so the `***` scene breaks sit at the left margin there. The Word export centers them.
